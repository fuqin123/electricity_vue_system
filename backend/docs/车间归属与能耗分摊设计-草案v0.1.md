## 三、一期数据模型方案

### 3.1 三个候选（含取舍）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| :-- | :-- | :-- | :-- | :-- |
| **A** | 新增 `production_workshop` 表 + `line.workshop_id`；车间级仪表改挂车间 | 语义最干净 | 迁移最大；汇总行的 `line_id` 仍需哨兵行承载，概念重复 | 备选 |
| **B（推荐）** | 把 `production_line` 升级为**组织节点表**：`node_type ∈ {workshop, line, aux}` + `parent_id` 自关联；**每个车间一条 workshop 节点**，即现有哨兵行的推广 | 迁移最小（加 2 列 + 改数据）；汇总唯一键与哨兵行机制**原样复用**；天然支持「碳水/制造」与「辅机一期/二期」 | 表语义变宽（`rated`/`product` 对辅机节点无意义） | **推荐** |
| **C** | 只给 `production_line` 加 `workshop_code` 字符串列 | 改动最少 | 「总表分摊到哪几条线」靠命名约定，制造车间进来即崩 | 不采纳 |

**选 B 的理由**：汇总表的唯一键依赖 `line_id`，而哨兵行机制是当初为「让唯一键对车间级总表仍然有效」
专门设计的（`数据库设计-v1.3.0.md §一.3`，有实测教训）。多车间只是把「一条哨兵行」推广成
「每车间一条」，属**机制的自然延伸**，不必推翻。

### 3.2 表结构增量

```text
production_line（升级为组织节点表）
  + node_type   VARCHAR(10)   workshop | line | aux     -- 由 line_type 扩写，保留 line_type 兼容
  + parent_id   INT NULL FK→self                        -- 产线/辅机的上级车间节点
  + sort / code / name 沿用

节点树（一期）：
  碳水车间 (WS-CARB, node_type=workshop)          ← 车间水/汽总表挂这里
    ├─ A1 (line)  ├─ A2 (line)  ├─ A3 (line)
    ├─ A4 (line)  ├─ A5 (line)  ├─ A6 (line)
    └─ （辅机一期不在本期范围，接入后作为 aux 节点挂这里）

节点树（后续）：
  制造车间 (WS-MANU, node_type=workshop)
    ├─ 其产线 …
    └─ 辅机二期 (aux)
```

> ⚠ **不建议**把辅助单元的仪表直接挂在车间节点上用 `role=aux` 区分：
> 那样会丢掉「一期/二期」的分组，且分摊的**数据源**无法被单一表达。
> 辅机接入时，应为每个辅机单元建一个 `node_type=aux` 节点，仪表挂在该节点上。

### 3.3 分摊结果的存放（对应冲突 C4）

| 方案 | 做法 | 评价 |
| :-- | :-- | :-- |
| ① | 汇总表唯一键增加 `source ∈ {metered, allocated}` | 语义最正确；需改三个汇总表的唯一键（一次迁移） |
| ② | 新增独立分摊汇总表 `energy_alloc_daily/monthly/yearly` | 不动现有表；但汇总查询要合并两处 |

**当前判断**：碳水车间**没有实测的产线级水/汽表**（只有车间总表），因此分摊值是「从无到有」，
与现有 `(line, WATER, day)` 行**不会冲突** → **一期可采用方案 ②**，改动面最小。
但只要将来某条产线装了独立水表，就必须换成 ①。建议在一期就**把 `source` 列预留在分摊表中**，
并约定 `energy_alloc_*` 表内 `source = 'allocated'` 恒为常量，为将来合并留路。

## 四、分摊口径设计

### 4.1 数学定义

```text
小时级（推荐最小粒度）：
  比例      ratio_i(h) = output_i(h) / Σ_j output_j(h)          j ∈ 本车间参与分摊的产线
  分摊值    alloc_i(h) = total_meter(h) × ratio_i(h)
  守恒       Σ_i alloc_i(h) + unallocated(h) = total_meter(h)
```

### 4.2 四条必须写死的边界规则

| # | 规则 | 理由 |
| :-- | :-- | :-- |
| R1 | **分母为 0 的时段不分摊**，总表值整体记入「车间未分摊余额」`unallocated` | 全车间停产时（CIP / 清洗 / 待机）总表仍有流量。若强行按产量分摊，分母为 0 会导致除零或整段丢失；留成「未分摊余额」既守恒又诚实 |
| R2 | 单条线产量缺失时，**该小时整段不分摊**（`quality = partial`），不缩小分母 | 缩小分母等于把「缺失的线」当成「零耗能」，与「缺数绝不补 0」同罪 |
| R3 | 守恒取整残差归入 `unallocated`，**不塞给某一条线** | 塞给某条线会让该线数字长期系统性偏高，且无人能解释 |
| R4 | 分摊值 `quality` **不得为 `ok`**，统一标 `allocated` | 分摊是估算值，界面必须能与实测值区分。这是「不产生假数字」铁律的落法 |

### 4.3 ★ 阻塞项：产量的采集粒度决定分摊粒度

| 产量粒度 | 可行的分摊粒度 | 说明 |
| :-- | :-- | :-- |
| **小时**（灌装机计数器 / PLC） | **小时级分摊**（首选） | 与 `energy_hourly` 同粒度，逐小时摊完再累加，日/月/年自动一致 |
| **班次**（MES 报工 / 人工填报） | **班次级分摊**，小时级分摊无法成立 | 小时级需求只能退化为「按班次总量 + 该小时是否生产」二次分配，精度下降且需要额外口径定义 |
| **日**（日报） | 只能**日级分摊** | 日内分布完全不可知，小时级图表不得展示分摊值 |

> **这是本方案唯一的一级阻塞项**。请确认产量的采集方式；若为班次/日报工，
> 分摊只能落在班次/日粒度上，**大屏逐小时的水/汽分摊曲线将不可提供**（只能给车间级实测曲线）。

## 五、公式引擎设计

### 5.1 定位与边界

公式引擎解决「不懂代码的人用加减乘除自定义指标」。它与分摊的关系是：
**分摊是一种对公式的特殊用法**（公式 = 总表 × 比例，且带归一化与守恒约束），
因此内部复用同一套求值器，但**对外是两类对象**，分开建模：

| 对象 | 表 | 用途 |
| :-- | :-- | :-- |
| 计算指标 | `calc_formula` | 通用加减乘除，产出「派生指标」 |
| 分摊规则 | `alloc_rule` | 总表/辅机 → 产线集合，带比例与守恒 |

### 5.2 表达式最小集（一期刻意做小）

```text
变量       M:<meter_code>           引用计量点的小时用量
           F:<formula_code>         引用其他公式（须防环）
常量       数字字面量
运算符     +  -  *  /  ( )  一元负号
聚合       SUM(集合)  AVG(集合)     集合按 车间/产线 选择器表达
```

**一期不做的**：条件判断（IF）、日期函数、字符串、跨单位换算。
理由：条件函数最容易把「缺数」用公式掩盖掉（例如 `IFNULL(缺数, 0)`），
与本项目「缺数绝不补 0」铁律正面冲突；确需时再评审加入。

### 5.3 四项保存前必过的校验

1. **语法**：可解析为 AST；
2. **引用**：变量/公式均存在；
3. **循环**：公式依赖图无环（拓扑排序检测）；
4. **量纲**：`kWh` 与 `m³`/`t` **不得相加**；除法产生复合单位时不作约束。

### 5.4 求值粒度与落库

- **统一在小时粒度求值**，结果落 `energy_calc_hourly`，再**复用现有累加口径**向上汇总。
  理由：避免「月直接由公式算」与「日累加」结果不一致——这正是 B-512 / B-523 一类缺陷的根源。
- 每次写入带 `formula_version`，查询默认取最新，历史可按版本回溯。

### 5.5 执行时机

| 时机 | 动作 |
| :-- | :-- |
| 每小时采集 + 聚合完成后 | 计算本小时派生值（与 `energy_hourly` 同节奏） |
| 每日 00:30 `summarize --rollup` | 顺带刷新当日派生与分摊 |
| 手工重算 | `manage.py calc --from --to [--formula CODE]`，**幂等** |

### 5.6 版本与历史重算（对应决策 D6）

改公式会**改变历史数字口径**。必须三选一并写死在界面流程里：

| 选项 | 行为 | 评价 |
| :-- | :-- | :-- |
| ① 只对今后生效 | 历史保持旧值 | 报表会出现口径断层，无法解释 |
| ② 全量重算 | 历史全部按新公式重写 | 上月报表会变，需提前告知使用方 |
| ③ **版本化 + 生效时间** | 历史按当时版本，新值从生效时间起 | **推荐** |

## 九、验收标准

1. **守恒断言**：任意小时内 `Σ(各线分摊值) + 未分摊余额 = 车间总表实测值`。固化为测试用例（参照现有 `ClosedDaySnapshotTests` 的写法）。
2. **粒度一致性**：分摊值逐小时累加 = 日分摊值 = 月分摊值（不得出现三者不等）。
3. **缺数不补 0**：产量缺失或总表缺失的时段，分摊值为 `null` + `quality=partial`，界面显示 `--`。
4. **可区分**：界面与接口能区分实测值与分摊值（`source` 字段），报表两者不混排。
5. **逐格比对**：大屏与后台同一日期的车间级/产线级数字逐格相等（沿用 v1.4.1 的验收方法）。
6. **可追溯**：任一分摊数字可回溯到「哪条规则、哪个版本、哪条总表读数」。

## 十一、建议分期

| 期 | 内容 | 前置依赖 |
| :-- | :-- | :-- |
| **一期** | 归属模型（碳水车间节点 + 6 线挂靠 + 仪表重挂）+ 车间级水/汽/电汇总口径修订 | B3、B4 |
| **二期** | 产量接入 + 分摊规则（水/汽 → 6 线）+ 守恒校验 | **B1**、B2 |
| **三期** | 公式引擎 + 前端公式设计器 + 版本与重算 + 权限审计 | 二期稳定 |
| 后续 | 制造车间节点 + 辅机一期/二期接入与分摊 | 一期机制复用 |

**为什么一期不含分摊**：归属是分摊的前提，而它**不依赖产量**、可立即落地并暴露现场问题（表挂错、网关不通）。
把归属与分摊拆开，可避免「产量还没接入 → 什么都做不了」的等待。
